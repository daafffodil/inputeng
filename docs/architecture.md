# Architecture

## 产品目标

`inputeng` 不是在线翻译器，而是“中文输入法候选注释层”：候选的中文文本负责上屏，英文只负责显示。

## 分层

1. **平台宿主层**：macOS 使用鼠须管 / Rime；Windows 首版使用小狼毫 / Rime。两端复用输入方案和 Lua 候选注释逻辑。
2. **候选注释层**：根据候选中文文本查询离线词典，把英文写入候选 comment / annotation。
3. **共享数据层**：平台共同读取 `shared/dictionary/bilingual_english.tsv` 的派生版本。
4. **运行数据层**：设置、个人短语、AI 队列和翻译缓存保存在各系统的用户数据目录，不进入项目源码。

## Windows 中文候选词库

Windows 继续复用小狼毫内置的拼音解析器，但不加载明月拼音中文词库。普通候选只来自逻辑主词库 `input_translate_core`，其固定导入 Rime Ice 的 `8105` 标准字表、3,000 权重门槛的 `base` 子集和 79 条受控现代词。`ext`、`tencent`、`others` 均不打包；在干净词库上保留 Rime 组句，并用 inputeng 个人短语层记住用户第一次成功组成的多片段短语。英文离线表和 DeepSeek 缓存只写候选注释，不生成中文候选。

## Windows 决策

首版不从零开发 Windows TSF 输入法。小狼毫已经提供系统输入、拼音引擎、候选窗、Rime 部署和 Lua 扩展能力；项目只维护自己的方案、注释层、离线词典、主题补丁和安全安装器。若以后需要完全独立品牌、设置程序或候选窗交互，再评估独立 TSF 实现。

## 运行数据边界

v0.5.3 已从产品和设置界面移除词频词云，同时停止采集新的上屏词频。现有历史词频文件保留在用户目录中但不再读取或展示，避免升级过程擅自删除用户数据。

## 候选翻译补全与显示规范

当前 CC-CEDICT 原始释义存在两类体验问题：部分候选没有精确词条，部分释义过长，使候选窗宽度不断变化。下一阶段按以下原则处理：

1. **统一短释义**：候选窗只显示一个最常用的简短义项，目标不超过 24 个英文字符；优先在单词边界缩短，不直接展示长解释、括号补充和多段释义。
2. **紧凑候选窗**：在短释义基础上把 Windows 候选窗限制为 160 至 300 的自动宽度，让英文紧跟中文，同时避免少数长释义把整窗撑得过宽。
3. **本地优先**：先查共享离线词典与本机 AI 补全缓存，命中时不联网。
4. **DeepSeek 只补缺口**：仅把当前页未命中的简体中文词组批量交给 `deepseek-v4-flash` 非思考模式，要求返回严格 JSON 和短英文释义；不发送此前上屏文本、输入上下文或应用内容。
5. **批量、延迟、缓存**：候选停止变化约 500 ms 后合并请求；成功结果永久写入本机缓存，失败结果短时间负缓存，断网或接口异常不得影响中文输入。
6. **密钥隔离**：API Key 只保存在系统凭据存储或受保护的本机配置中，不进入源码、安装包、Vault、日志或候选缓存。

Rime Lua filter 继续只负责快速本地查询和显示，不在候选生成线程中直接等待网络。Windows v0.2.0 已把实时补全放入独立 PowerShell helper：Lua 写入缺词队列，helper 延迟合并调用 DeepSeek，使用 Windows DPAPI 保存 Key，并通过版本文件让 Lua 在下一次候选刷新时重载缓存。因为 Rime Lua 不能像水杉的原生 Server 一样自然地异步重绘当前候选窗，首次遇到极少数新词时，翻译可能在下一次候选刷新后出现。若以后必须在同一候选窗内无感刷新，再评估原生 librime 插件，而不是用同步网络请求牺牲输入延迟。

Windows v0.4.1 进一步收紧 Lua 热路径：构建时只保留 `input_translate_core` 实际可能产生的简体中文英文键，并预生成最长 24 字节的显示释义；运行时把 AI 开关、AI 缓存版本和个人短语版本检查限制为每秒最多一次，缺词按候选页批量追加，并固定候选窗宽度。网络仍完全位于后台 helper，普通按键阶段不等待 API。

Windows v0.4.2 把候选窗调整为 220 宽，保持 15 点中文与 12 点灰色英文，设置垂直居中并收紧横向边距。官方小狼毫 0.17.4 的竖排渲染器会把注释统一放到本页最长候选之后；扩展层可以调整字号、颜色、间距和窗口宽度，但不能在不替换前端的情况下改为逐候选不对齐布局。

Windows v0.4.3 进一步发现固定 `min_width: 220` 会触发小狼毫把每行注释向候选框右侧补齐，使短页面出现远大于最长中文候选所需的空白。现改为 `min_width: 120`、`max_width: 220`，保留有限自适应宽度，并把英文从 12 点降为 10 点；这能消除固定窗口叠加的右移，但不会改变小狼毫按本页最长候选统一对齐注释的底层规则。

Windows v0.4.4 把中文公开主词库进一步分层。固定版本 Rime Ice 完整 `base` 作为上游快照保存在 `platforms/windows/upstream/`，构建时只选择权重不低于 5000 的行生成安装用 `cn_dicts/base.dict.yaml`，由 543,012 条收紧到 125,999 条；`8105` 规范汉字表、Rime 本机词频和 inputeng 个人短语层不变。这样删除的是未经用户选择的低频公开词，不会删除用户已确认的个人组合词，也保留了以后调整阈值并重新生成的能力。

Windows v0.5.7 将基础词入选门槛从 5,000 调整为 3,000，并对已确认的低质量词保留显式排除。基础词增加到 164,199 条，受控现代补充增加到 79 条；现代层中的重复词不再进入基础层，避免重复候选。这样扩大常见生活词覆盖，同时不恢复完整长尾表。

Windows v0.5.8 将设置页从开发诊断视图收敛为用户可理解的词库说明：只展示中文核心词库与离线双语释义的总量和筛选依据，不再展示内部子库、个人学习条数、人工修正、DeepSeek 缓存、待处理队列、更新时间或输入方案说明。
